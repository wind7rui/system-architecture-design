# 质量属性目录（NFR Catalog）

阶段2推理时读取本文件，确保不遗漏跨切面关注点。架构形态由质量属性驱动，不是由流行技术驱动。

用法：先识别哪些是"驱动属性(D)"（决定架构形态的），哪些是"重要(I)"，哪些是"约束(C)"（硬性门槛）。每个质量属性都要落到**场景 + 量化指标**，而非空泛形容词。

---

## 质量属性全景

### 1. 性能 Performance
- 响应时间：P50/P95/P99 延迟目标
- 吞吐量：QPS/TPS（峰值/均值）
- 并发：同时在线/并发请求数
- 资源利用率：CPU/内存/IO 上限

### 2. 可扩展性 Scalability
- 水平扩展：能否加机器线性扩容
- 数据扩展：分库分表/分区策略
- 弹性：自动扩缩容响应时间
- 状态无关化：会话/状态外置程度

### 3. 可用性 Availability
- 可用率目标：99.9% / 99.95% / 99.99%
- 故障域隔离：单点消除
- 优雅降级：部分依赖故障时行为
- 维护窗口：热升级能力

### 4. 可靠性/容错 Reliability
- 失败重试与幂等
- 熔断/限流/隔离（舱壁模式）
- 超时控制
- 死信队列与补偿

### 5. 一致性 Consistency
- 强一致 / 最终一致 / 因果一致 的适用边界
- 分布式事务策略：2PC / Saga / TCC / 事件+补偿
- 幂等保证
- 缓存一致性

### 6. 数据持久性 Data Durability
- 数据丢失容忍度（RPO）
- 副本策略与备份
- 归档与冷存储

### 7. 安全性 Security
- 认证（Authentication）
- 授权（Authorization：RBAC/ABAC）
- 传输与存储加密
- 密钥管理
- 输入校验与注入防护

### 8. 合规 Compliance
- 法规：GDPR / 等保 / PCI-DSS / HIPAA / 金融监管
- 数据主权与跨境
- 审计日志与可追溯
- 数据保留与被遗忘权

### 9. 可维护性 Maintainability
- 模块化与耦合度
- 代码可读性/规范
- 测试覆盖与可测性
- 文档完备度

### 10. 可部署性 Deployability
- CI/CD 流水线
- 蓝绿/灰度/滚动能力
- 回滚机制与时间
- 配置管理（动态配置）

### 11. 可观测性 Observability
- 指标（Metrics）
- 日志（Logs）
- 链路追踪（Traces）
- 告警与 SLO/错误预算

### 12. 可运维性 Operability
- 运维自动化程度
- Runbook 完备度
- 自愈能力
- 容量规划与压测

### 13. 可扩展演进性 Extensibility
- 接口版本化
- 插件化/扩展点
- 协议兼容性
- 向前/向后兼容

### 14. 可测试性 Testability
- 测试分层与覆盖
- 测试环境与数据
- 契约测试
- 性能/混沌测试

## 典型权衡矩阵

不同质量属性常存在张力，决策时显式权衡：

| 张力对 | 典型取舍 |
|--------|---------|
| 一致性 vs 可用性 | CAP：网络分区下二选一 |
| 一致性 vs 延迟 | 同步协调通常增加通信等待，可能影响延迟 |
| 性能 vs 可维护性 | 优化手段常增复杂度 |
| 可用性 vs 成本 | 多副本/多活增加成本 |
| 安全 vs 便利 | 强认证影响体验 |
| 灵活 vs 简单 | 过度抽象增加理解成本 |

## 驱动属性识别法

问自己：**如果这个属性不达标，系统就失败**--那就是驱动属性。

- 交易系统：一致性 + 可用性 是驱动
- 实时推荐：延迟 + 吞吐 是驱动
- 审计系统：一致性(不丢) + 合规追溯 是驱动
- 内容平台：可扩展性 + 可用性 是驱动
- IoT 数据平台：吞吐 + 可扩展性 + 数据持久性 是驱动

识别驱动属性后，架构选型围绕它做--其他属性作为约束或权衡项处理。
