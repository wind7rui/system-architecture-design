# 访谈问题清单（阶段1）

按主题分组的问题清单。**不要一次全问**--按主题分批，若环境提供 `AskUserQuestion` 或等效工具，优先用结构化选项呈现（≤4 题/次）；否则直接在对话中分批提问。用户已给的直接跳过，只补缺口。

访谈目的：把模糊诉求收敛为"可做架构推理的事实与约束"。判断停止时机--当足以做出关键决策（服务边界、一致性策略、存储选型、部署形态）时即停。

---

## 主题 A：业务背景与范围

1. 这个系统解决的核心业务问题是什么？谁是主要使用者？
2. 有哪些核心业务场景？（请举 3-5 个最重要的）
3. 系统边界：哪些能力归本系统，哪些归外部？上下游系统分别是什么？
4. 主要干系人是谁？他们各自最关心什么？
5. 有无明确的非目标（不做什么）？

## 主题 B：规模与性能（决定架构形态的关键）

1. 当前与预期的用户量/日活？（当前 vs 1年 vs 3年）
2. 核心场景的峰值 QPS/TPS？均值呢？（拿不到就问量级：百/千/万/十万级）
3. 对延迟的敏感度？（实时交互 <100ms？准实时？批处理可分钟级？）
4. 数据量级与增长？（GB/TB/PB，年增长率）
5. 是否有明显波峰波谷？（如电商大促、教育开学季）

## 主题 C：数据与一致性

1. 哪些数据要求强一致？哪些可最终一致？（如库存扣减 vs 用户行为日志）
2. 是否存在跨服务/跨库事务需求？能否接受最终一致+补偿？
3. 是否需要审计追溯/事件回放？（金融、合规场景常见）
4. 数据读写比？是否有明显读多写少或写多读少？
5. 数据保留要求？（保留多久、冷热分层、归档）

## 主题 D：可用性与容灾

1. 可用性目标几个 9？（99.9% 年停 8.8h / 99.95% 停 4.4h / 99.99% 停 52min）
2. 可接受的 RTO（恢复时间）/ RPO（数据丢失）？
3. 是否需要多活/异地容灾？还是单可用区主从够用？
4. 故障期间能否降级服务（只读/部分功能）？

## 主题 E：安全与合规

1. 是否有合规要求？（GDPR、等保、PCI-DSS、金融监管、医疗数据）
2. 数据是否涉及敏感个人信息？是否跨境传输？
3. 认证授权方式？（现有 SSO？OAuth2？自定义）
4. 审计日志要求？（哪些操作必须留痕、保留多久）
5. 部署形态对安全的影响？（公网暴露范围、信任边界）

## 主题 F：运维与部署

1. 部署目标环境？（公有云/私有云/混合/私有化交付/边缘）
2. 是否有现成基础设施？（K8s？公司中间件？统一日志/监控平台）
3. 是否有专职运维/SRE？团队对运维自动化的要求？
4. 发布节奏与可用窗口？回滚能力？
5. 基础设施成本是否有上限？

## 主题 G：团队与组织约束（Conway 定律）

1. 研发团队规模与技能栈？（语言/框架/熟悉度）
2. 组织结构如何？是否有独立的前后端/运维/数据团队？
3. 是否有必须复用的内部系统/中间件/组件？
4. 团队对引入新技术的接受度？（保守/开放）
5. 交付节奏与人力配比对架构拆分的约束？

## 主题 H：演进与风险

1. 是否有明确的阶段化目标？（MVP -> V2 -> V3）
2. 上线时间节点？（硬截止？）
3. 你认为最大的技术风险是什么？
4. 是否存在历史包袱/遗留系统需集成或迁移？
5. 哪些是已知的不确定项/假设？（业务未定的、技术未验证的）

---

## 访谈后必做

用 3-5 行向用户**复述关键事实与约束**，请用户确认。例如：

> 我理解：这是一个面向 C 端的电商订单系统，峰值预估 5 万 QPS，支付强一致不可超卖，需 99.95% 可用性，部署在公司私有云 K8s，团队 8 人 Java 栈，3 个月内 MVP 上线。核心约束是金融级审计追溯。请确认以上理解是否准确，我再开始产出架构文档。

可交互环境中确认后再进入阶段2推理与阶段3产出。非交互环境按主文件规则记录显式假设，继续产出草稿。这一步能避免方向跑偏后大规模返工。
